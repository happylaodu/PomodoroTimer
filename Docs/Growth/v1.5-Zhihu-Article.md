# 番茄钟也能生成专业报告了？我给自己的1.5MB应用加了数据导出

## 前情提要

三个月前，我写了一个只有 1.5MB 的 macOS 番茄钟应用（[上一篇文章](链接)），主打轻量、免费、开源。

发布后收到了不少反馈，其中有个建议让我印象很深：

> "能不能导出数据？我想看看自己这个月总共专注了多少小时，做 PPT 汇报用。"

这个需求很合理 —— **如果数据无法导出，那记录再多也只是自嗨。**

于是 v1.5 版本就做了这个功能：**统计数据导出 + PDF 专业报告**。

## 🎯 为什么要导出数据？

作为番茄工作法的重度用户，我发现记录专注时间有很多场景需要导出数据：

**学生党：**
- 考研复习总结："这个月我专注学习了 120 个小时"
- 论文进度汇报："过去两周每天平均专注 8 个番茄钟"
- 自我激励："看到图表上升趋势，很有成就感"

**打工人：**
- 周报/月报："本月完成深度工作 80 小时"
- 项目复盘："这个项目投入了 200+ 番茄钟"
- 效率分析："找出自己最高效的时间段"

**自由职业者：**
- 客户汇报："为你的项目投入了 XX 小时"
- 时间管理："分析哪些天效率最高/最低"
- 收费依据："按实际专注时长计费"

**隐私友好的数据，应该完全由用户掌控。**

## 🛠 技术实现：如何在 1.5MB 里加这些功能？

很多人可能会想：导出功能 = 引入第三方库 = 体积变大。

但实际上，**依然没有用任何第三方库，依然是 1.5MB**。

### CSV 导出

用 Swift 原生的字符串拼接：

```swift
// 简化示例
var csv = "日期,番茄钟数,累计总数\n"
for (date, count) in history {
    csv += "\(date),\(count),\(total)\n"
}
try csv.write(to: url, atomically: true, encoding: .utf8)
```

没有依赖，没有复杂库，就是最基础的文件写入。

### PDF 生成

用 macOS 原生的 PDFKit：

```swift
// 创建 PDF 上下文
let pdfMetaData = [
    kCGPDFContextCreator: "Pomodoro Timer Lite",
    kCGPDFContextAuthor: "User"
]
let format = UIGraphicsPDFRendererFormat()

// 绘制内容
let renderer = UIGraphicsPDFRenderer(bounds: pageRect, format: format)
let data = renderer.pdfData { context in
    context.beginPage()
    // 绘制标题、表格、统计...
    drawTitle(in: context)
    drawStats(in: context)
    drawTable(in: context)
}
```

**关键点：**
- PDFKit 是系统自带框架，不增加体积
- 手动绘制布局，完全可控
- 生成的 PDF 文件很小（通常 < 50KB）

### 文件保存对话框

用原生的 NSSavePanel：

```swift
let savePanel = NSSavePanel()
savePanel.allowedContentTypes = [.pdf]
savePanel.nameFieldStringValue = "Pomodoro_Weekly_Report_\(today).pdf"
savePanel.begin { response in
    if response == .OK, let url = savePanel.url {
        // 保存文件
    }
}
```

**优点：**
- 原生对话框，用户熟悉
- 自动建议文件名
- 支持所有系统功能（iCloud、最近位置等）

## 💡 开发中的一些思考

### 1. 关于功能取舍

在开发导出功能时，我也考虑过要不要加：
- 导出为 Excel 格式（.xlsx）
- 生成可视化图表（折线图、饼图）
- 导出为 JSON、Markdown 等格式
- 云端自动备份

**最后的选择：**

✅ **CSV** - 最通用，用户可以用任何工具打开
✅ **PDF** - 最专业，可以直接分享和打印
❌ **Excel** - 需要第三方库，增加体积
❌ **图表** - 应用内已有 7 天图表，够用
❌ **JSON/Markdown** - 受众太小
❌ **云备份** - 违背"隐私优先"原则

**保持克制，只做必要的。**

### 2. 关于沙箱权限

macOS 应用有严格的沙箱限制，导出文件需要获取权限。

最初的实现方式会导致对话框无法显示，花了一天时间排查：

**问题：**
- 设置窗口的 `level` 设置为 `.floating`，导致 NSSavePanel 显示在窗口下方

**解决：**
- 移除浮动级别
- 将保存对话框作为 sheet 附加到设置窗口
- 正确设置沙箱 entitlements

**教训：**
原生开发看似简单，但细节很多。**每个小功能都要考虑系统机制。**

### 3. 关于本地化

导出的 CSV 和 PDF 支持中文和英文：

| 语言 | CSV 表头 | PDF 标题 |
|------|---------|---------|
| English | Date, Sessions, Total | Pomodoro Statistics Report |
| 简体中文 | 日期, 番茄钟数, 累计总数 | 番茄钟统计报告 |

实现方式：使用 `NSLocalizedString`

```swift
let header = NSLocalizedString("csv.header.date", comment: "日期")
```

**好处：**
- 根据系统语言自动切换
- 保持应用的一致性
- 尊重不同地区用户

## 🎯 数据隐私：为什么不做云同步？

有人建议加云同步功能，把数据自动上传到 iCloud。

我的答案是：**不做。**

**原因：**

1. **违背设计理念** - 这个应用的核心是"隐私优先"
2. **不是所有人都需要** - 大部分人只在一台 Mac 上用
3. **增加复杂度** - 需要处理同步冲突、账号系统
4. **增加体积** - CloudKit 框架会让体积翻倍

**替代方案：**
- 导出 CSV，自己上传到网盘
- 用 Time Machine 备份整个 Mac
- 手动拷贝应用数据文件夹

**数据在本地，完全由用户掌控，这才是真正的安全。**
