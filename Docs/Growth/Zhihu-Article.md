## 📄 完整文章内容

```markdown
# 我开发了一个 1.5MB 的 Mac 番茄钟应用，比同类产品小 90%

## 为什么又做一个番茄钟？

作为一个番茄工作法的重度用户（每天 8-10 个番茄钟），我试过市面上几乎所有的番茄钟应用。

然后我发现了一些很奇怪的现象：

**一个计时器，为什么需要 30-50MB？**

我打开 Activity Monitor 看了一下，有的番茄钟应用内存占用能到 200-300MB。这让我很困惑 —— 一个计时器需要这么多资源吗？

仔细看了一下，原来里面塞了：
- 数据统计（需要联网上传到云端）
- 社交功能（什么 Pomodoro 社区、打卡排行榜）
- 第三方广告 SDK
- 各种分析追踪库
- 云同步功能（我一个人用，同步给谁看？）

**更让人无语的是定价模式：**

- 免费版：限制功能，每天只能用 3 个番茄钟
- 标准版：¥68 买断
- Pro 版：¥18/月 或 ¥128/年

一个计时器，为什么要订阅制？我只是想专注工作 25 分钟，不是想加入什么"生产力革命"。

**隐私问题：**

打开隐私政策一看，收集的数据包括：
- 设备信息
- 使用时长
- 专注时段
- 应用使用情况
- 甚至包括"您在使用应用时的其他应用活动"

我的专注时间，凭什么要上传到你的服务器？

---

## 我想要的番茄钟是什么样的？

其实很简单：

1. **轻量** - 一个计时器，不需要加载一堆乱七八糟的东西
2. **免费** - 计时功能本身不应该收费
3. **隐私** - 我的数据留在我的 Mac 上，不上传
4. **简单** - 功能够用就好，不要花里胡哨

既然找不到，那就自己写一个。

---

## 技术选择：为什么能做到 1.5MB？

### 使用原生技术栈

**Swift + SwiftUI + AppKit**

完全使用苹果原生框架，零第三方依赖。

很多应用为什么大？因为引入了一堆第三方库：
- 数据统计：Firebase (10MB+)
- 广告：Google AdMob (8MB+)
- UI 框架：React Native / Electron (30MB+)
- 网络库：各种第三方 HTTP 库

而我只用了系统自带的：
- SwiftUI - 界面
- AppKit - 菜单栏集成
- UserDefaults - 本地存储
- Charts - 图表（iOS 16+ 原生）

**最终结果：编译后的 .app 只有 1.5MB**

### 菜单栏应用设计

传统应用会在 Dock 栏显示图标，占用空间。

番茄钟其实更适合做成菜单栏应用：
- 不占用 Dock 空间
- 随时可见（工作时长）
- 点击即用

技术实现很简单：
```swift
// 隐藏 Dock 图标
LSUIElement = true

// 创建菜单栏图标
let statusItem = NSStatusBar.system.statusItem(withLength: NSStatusItem.variableLength)
```

### 本地数据存储

所有数据用 UserDefaults 存储在本地：
- 工作时长记录
- 自定义设置
- 统计数据

不需要数据库，不需要云同步，不需要服务器。

简单、可靠、隐私。

## 开发过程中的一些思考

### 关于功能取舍

开发过程中，我也想过要不要加：
- 任务列表
- 云同步
- 数据导出
- 更详细的统计

但最后都砍掉了。

**原因很简单：保持专注于核心功能。**

番茄钟的核心是什么？帮助你专注 25 分钟。

其他功能都是锦上添花，但会带来复杂度：
- 任务列表：有专门的 Todo 应用（Things、OmniFocus）
- 云同步：需要服务器、账号系统、隐私问题
- 数据导出：大部分人不会用

**做减法比做加法难。**

保持简单，就是保持可靠。

### 关于定价

完全免费，MIT 开源。

为什么不收费？

1. **这是个人项目** - 我自己在用，顺便分享
2. **功能简单** - 一个计时器，收费不太合适
3. **想法很简单** - 如果能帮到别人，那就是意外收获

开源的好处：
- 代码透明，没有后门
- 任何人都可以 fork 修改
- 社区可以贡献代码

## 为什么选择 macOS？

有人可能会问：为什么不做 iOS 版？

**因为使用场景不同。**

番茄工作法通常是：
- 坐在电脑前工作/学习
- 需要屏蔽手机干扰
- 计时器在电脑上更合理

如果做 iOS 版：
- 失去了菜单栏的便利性
- 反而会让人一直看手机
- 和番茄工作法的初衷矛盾

所以专注做好 macOS 版本。
